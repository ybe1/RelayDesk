## 阶段 1：brainstorm 定稿（2026-09-19）

**用户关键原话：**“把 query_faq 的内部实现从关键词查表升级成向量语义检索，工具的入参出参契约保持不变”；“BGE-M3 的嵌入模型服务用云端的，比如 Hugging Face 或者硅基流动都可以”。

**关键产出：**读取现有工具/数据库/部署结构，用 Context7 核对 Milvus、PyMilvus、BGE-M3、LangChain 切分和硅基流动接口。用户确认分阶段离线任务、演示 Markdown 文档、跨批合并同义问法、硅基流动 BGE-M3、Milvus Docker、独立每日 02:00 抽取任务与 dense 单路在线查询。设计 spec：`docs/superpowers/specs/2026-09-19-ch03-dense-knowledge-design.md`。

**用户拒绝或纠偏：**最初推荐本机加载 BGE-M3，用户改为云端嵌入服务；按硅基流动方案修订。用户提供的 DDL 实际含 `knowledge_chunks` 与 `qa_extraction_staging` 两表，均纳入设计。

**翻车与返工：**无实施返工。本机约 16 GB 内存、检查时仅约 2.8 GB 空闲，Milvus standalone 有资源风险；spec 中设真实冒烟与固定技术栈失败时停下询问的门槛。尚未执行建表或启动 Milvus。

## 阶段 2：课程对照后的 spec / plan 修订（2026-09-22）

**用户关键原话：**沿用任务要求“工具的入参出参契约保持不变”“我拒绝或纠偏了什么、翻车与返工”；本轮用户要求对照外部课程文档修改后执行，并明确纠正继续使用 Docker Milvus standalone。执行方式沿用 ch01 留痕中直接 main 与 Subagent-Driven 的偏好。

**关键产出：**重写 `docs/superpowers/specs/2026-09-19-ch03-dense-knowledge-design.md` 和 `docs/superpowers/plans/2026-09-19-ch03-dense-knowledge.md` 为 9 个可执行交付任务，保留原两表 DDL 附录。新增 /kb 六区、/admin、预览/录入/暂存/库存/最近/API、自测、固定白名单作业与日志/停止、seed-conv 幂等演示会话、确认后仅 Ch03 reset。线上 Milvus 返回 question/answer/category 保留实际 keyword/matches 契约，继续同步 SessionLocal；文档和暂存共用规范化 QA 指纹，保留同标题多块；后端 TDD、前端浏览器验证、真实故障恢复及标注评估分别设门槛。Windows 作业使用固定 Python argv，Makefile 保留等价别名，避免复制仅 POSIX 的进程控制。
