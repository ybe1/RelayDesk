# Ch05 开发过程

## Brainstorm 定稿与 spec 自审（2026-10-02）

**用户关键原话：**“Workflow 确定性编排做骨架，主力 Agent 作为骨架里的核心节点”；“转人工、建工单是两件事”；“确认采用 AsyncSqliteSaver”；明确闲聊规则“是”、预算“接受”、父图加子图“符合”、按钮设计“继续”、删除create_ticket自动转人工副作用“接受”。

**关键产出：**设计文档 `docs/superpowers/specs/2026-10-02-ch05-workflow-agent-design.md`，包含七类固定分流、裸循环与Agent子图、前置置信度闸、预算、AsyncSqliteSaver、SSE、独立确认动作和验收方案。通过Context7查官方LangGraph持久化、子图和流式接口。spec自审完成；待用户审阅spec后编写plan，尚未写产品代码或建表。

**用户拒绝或纠偏：**选择官方AsyncSqliteSaver而非新增PostgreSQL或社区MySQL checkpointer；确认常见闲聊先规则拦截以满足零模型调用；明确本章SQLite是本机持久化、不是多实例生产存储。用户接受create_ticket只创建工单、不修改转人工状态。

**翻车与返工：**现有create_ticket仓储会顺带将会话改为已转人工，违反两个动作独立，已在设计阶段发现并获得纠正授权。原需求“意图模型识别”和“闲聊零模型”存在边界冲突，通过完整短句闲聊白名单前置解决。预算必须覆盖检索内部Query理解，不能只统计Agent；设计补充这一边界和跨库非原子限制。
