# Ch07 三层会话上下文 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. 用户已选择Native，保留执行偏好：主代理实施全部任务，仅最终一次独立审查，不派逐任务实施者。

**Goal:** 当前会话完整历史保真，在有限模型窗口内分层投影与后台追加摘要，并提供可切换的会话侧栏。

**Architecture:** MySQL持久化用户/助手消息、边界与摘要段，checkpoint保存完整工具往返。纯计数/分层函数生成模型输入副本；应用内有界摘要任务在短事务中追加新段与推进边界。工作流统一使用该投影，最终请求完整写日志。

**Tech Stack:** 现有FastAPI、SQLAlchemy/MySQL、LangGraph add_messages/AsyncSqliteSaver、LangChain trim_messages，原生HTML/CSS/JavaScript。

**Spec:** docs/superpowers/specs/2026-10-02-ch07-context-design.md（用户已书面确认，设计提交b1a04af）。

## Global Constraints

- 只处理当前conversation_id；不跨会话、不建用户画像、不增历史向量检索/主题重要度策略。
- 两步SQL都apply，按原DDL字段类型/索引/NULL/注释匹配；不自行给摘要表加外键。
- 新tool结果只在checkpoint，MySQL仍存user/assistant原文与调用申请；旧tool记录不删除。
- S≤L；id≤S已摘要、S<id≤L层2、id>L层1；边界只前移，按完整用户轮切分。
- 旧摘要段只追加、不重压；LLM调用不持数据库锁；提交成功才推进S。
- 输入固定system/tools → 层2 → 层1 → 当前用户句 → 摘要/证据合并资料 → 本轮工具往返。
- 统一计数；演示W=18000/O=2000/U=2000/A=3/T=1200/K=5，初始H=5650/H1=3954/H2=1695。
- B=1600/E=180/Q0=600/C=400/N=40；M=max(450,ceil(0.02W))。额度必须容纳实际输入，不硬编码H。
- 完整State不使用RemoveMessage裁剪，模型输入投影不写回原历史。
- log/app.log UTF-8：history_ctx每轮必打，model_ctx每次实际请求必打；日志不含密钥/Authorization。
- Context7核对具体库/API后动手；代码TDD，Prompt/数据用标注样例验证。
- Native原工作区实施、每任务本地提交/即时dev-notes、不推远端；单应用实例。
- 用户在VS Code自行启动服务；不代启动8000/8001、不打开用户网页。
- 第七章新数据外发单独授权；评估只用合成数据，不复用私有会话。

## Review Focus

1. checkpoint已保存tool结果但MySQL没tool行：不能把成功调用误标中断或重执行（Task3）。
2. 单个超大历史轮/并行工具批次：不能拆配对、不能按行数漏掉结果体积，也不能挤掉当前用户句（Task4/6）。
3. 摘要执行时L继续前移或进程取消：不能回退S、重复段或丢未覆盖事实（Task5）。
4. 资料截短、摘要混入旧段事实：不能丢资格条件后批准退款、不能把摘要订单当当前用户明确订单（Task5/6）。
5. 切换会话时SSE迟到/列表请求失败/匿名用户不匹配：不能串气泡、产生业务动作或泄露历史（Task7/8）。

共享类型由Task1定义：

```python
@dataclass(frozen=True)
class ContextConfig:
    window: int = 1_000_000
    output: int = 4_000
    user_input: int = 4_000
    steps: int = 5
    tool_result: int = 2_400
    rerank_k: int = 10
    desired_turns: int = 40
    prefix: int = 1_600
    evidence_per_hit: int = 180
    summary_reserve: int = 600
    call_overhead: int = 400

@dataclass(frozen=True)
class BudgetBreakdown:
    fixed: int
    transient: int
    steady: int
    history: int
    layer1: int
    layer2: int
    summary: int
    margin: int

@dataclass(frozen=True)
class LayerAnchors:
    summary_upto: int = 0
    layer1_from: int = 0

@dataclass(frozen=True)
class HistoryRecord:
    message: BaseMessage
    owner_msg_id: int  # tool用对应assistant申请的MySQL id
    turn_id: str

@dataclass(frozen=True)
class SummarySegment:
    seq: int
    from_msg_id: int
    upto_msg_id: int
    content: str

@dataclass(frozen=True)
class HistoryProjection:
    anchors: LayerAnchors
    layer1: tuple[BaseMessage, ...]
    layer2: tuple[BaseMessage, ...]
    summary: str
    layer2_tokens: int
    omitted_ranges: tuple[tuple[int, int], ...]

@dataclass(frozen=True)
class SummaryBatch:
    conversation_id: int
    expected_summary_upto: int
    upto_msg_id: int
    source: tuple[HistoryRecord, ...]
    previous_segments: tuple[SummarySegment, ...]
```

BaseMessage来自langchain_core.messages，tuple用于防止投影修改原对象。None锚点进入这些类型时转换0。
